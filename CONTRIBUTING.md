# Contributing to mediagrep

Thanks for helping. Bug reports, file-naming conventions mediagrep should
recognize, and patches are all welcome.

## Reporting a problem

Open an issue with the command you ran, what you expected, and what
happened. If it involves a particular file, the output of
`mediagrep --fields FILE` usually says more than the file itself, and is
much easier to share.

## Building and testing

You need a C++17 compiler, CMake 3.16 or later, and MediaInfoLib (see the
README for each platform).

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/mediagrep_tests
```

The tests use [doctest](https://github.com/doctest/doctest). Run a subset
with `--test-case='*progress*'`. The parser, evaluator and output
formatting are tested against an in-memory metadata source; the
MediaInfoLib backend and the command line run against the small files in
`tests/fixtures`. Those are generated by `tests/fixtures/make.sh` with
ffmpeg, so a new fixture should be added there rather than as an
unexplained binary.

CI builds and tests every push on Linux, macOS and Windows, with the
library both loaded at runtime and linked at build time.

## Changes

- Add a test that fails without your change.
- Keep the portability constraints: C++17, no `std::filesystem` (some
  NAS toolchains lack it), no dependencies beyond MediaInfoLib and the
  standard library. Platform code belongs in `fsys`, `term` and `thread`.
- Match the surrounding style: 4-space indents, lines up to 100
  columns, comments that say why rather than what.
- A new command-line option needs a line in the help text, the README
  and `docs/mediagrep.1.in`; a test checks that the man page lists every
  option in the help.
- Record user-visible changes under the top section of `CHANGELOG.md`.

The design and the reasons behind it are in
`docs/superpowers/specs/2026-10-16-mediagrep-design.md`; update it when a
change alters a decision written there.
